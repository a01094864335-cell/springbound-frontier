# 프롤로그 완성도 개선·구현 계획

작성: 2026-10-28 · 상태: **초기 계획 / 최신 구현은 아래 업데이트 참고**

> 2026-10-30: 게임 대사·생활 진행·첫 전투·패배/재도전·아이템 비환급·승리 후 처치를 구현했습니다. [첫 전투의 실제 범위와 검증](first-battle.md). 아래 표와 체크리스트는 작성 당시 기준이며, 최종 미술·음향·Windows 완주 검증은 아직 남아 있습니다.

## 목표와 완료의 의미

에일의 고향 생활에서 레온과의 첫 전투, 돌샘 도착까지 하나의 프롤로그로 완주할 수 있게 만듭니다. 중심 경험은 동료에게 정이 드는 이야기입니다. 전투는 두려워하는 에일과 부상당한 레온이 서로에게 도움을 주는 사건이어야 합니다.

완료는 공간을 걸어갈 수 있다는 뜻에 그치지 않습니다. 정식 이벤트 흐름, 전투·패배·재도전, 저장·불러오기, 캐릭터 동작, 대사·음향이 연결되고 목표 Windows 환경에서 검증된 상태를 뜻합니다. 목표 체험 시간은 기존 결정대로 약 30~45분이며 반복 이동이나 강제 대기로 분량을 채우지 않습니다.

이 문서는 실행 순서와 검토 기준을 제안하는 계획입니다. 아직 미정인 규칙·수치의 승인이나 게임 구현 완료를 뜻하지 않습니다. 작업자는 단계별 결과와 근거를 기록하며, 추가 구현은 별도 PR로 제출합니다.

## 유지할 규칙과 이번 범위

- Godot 기반 Windows PC 출시 목표, 현재 Mac에서 개발 테스트. 웹 테스트는 현재 필수 기준이 아닙니다. Godot 4.6.3·Compatibility는 현 빌드의 구성으로 유지하며 변경이 필요하면 비교 검증합니다.
- 1280×720 기준 16:9, 글자 확대·키 변경, 화면 상하좌우 이동. 과거의 대각선 이동 제안을 되살리지 않습니다.
- 탐험 맵에서 화면 전환 없이 전투. 명령 시 완전 정지, 별도 입력으로 재개. 기본 공격은 지정 적을 반복 공격합니다.
- 프롤로그는 **에일 1명 전투 + 검 일반 공격 + 회복 아이템**. 레온은 싸우지 않습니다. 본편 4인 전투를 염두에 두되, 동료 편성·마법 전체를 먼저 만들지는 않습니다.
- 아이템은 생존한 사용자를 지정하고, 거리 제한 없이 즉시 효과가 나며 사용자에게 짧은 행동 후 대기가 생깁니다. 파티 공통 재사용 시간은 넣지 않습니다.
- 전투 후 생존자의 체력·마나는 유지. 재도전은 전투 직전 상태를 복원하되 전투 중 소비한 아이템을 돌려주지 않습니다.
- 높낮이로 사거리·명중·피해를 보정하지 않습니다. 일반 공격 바닥 경고는 추가하지 않습니다. 범위 공격 경고는 실제로 범위 공격이 있는 경우에만 사용합니다.
- 텍스트 대사·표정 초상화·BGM·효과음을 포함하며 음성은 넣지 않습니다.

### 00. 기준선과 상세 흐름 고정

- [ ] 현재 Mac 실행 영상·스크린샷과 커밋을 기준선으로 남깁니다. 초기 화면·네 맵·대화·한 칸 이동을 기록합니다.
- [ ] P-01 아침 심부름 / P-02 약과 출발 준비 / P-03 산길 흔적 / P-04 빌린 검 / P-05 동행과 돌샘의 세부 이벤트를 목록화합니다.
- [ ] 최초의 과거 도주, 마르타 편지, 마지막 요새·유적 연출은 대본상 가안으로 표시합니다. 스포일러 정도와 정확한 대사를 검토한 뒤 포함 여부를 고정합니다.
- [ ] 한국어 Windows PC CD판의 미검증 규칙은 조사 대장에 근거·판본·한계를 기록합니다. PS·PSP의 규칙이나 추측을 원작 사실로 쓰지 않습니다.
- [ ] 프롤로그에 필요한 미정 항목(이동 완료 후 행동, 공격 상태별 명령 취소, 정지 중 아이템 처리, 회피 방식, 재도전 소비 기록)을 우선 좁힙니다. 증거가 없으면 검증용 임시 규칙이라고 명시하고 출시 기준 확정으로 취급하지 않습니다.

완료 기준: 작업자가 같은 순서와 목표를 읽고 사건을 재현할 수 있고, 구현자가 몰래 결정해야 하는 핵심 규칙이 드러나 있습니다. 원작 조사 전체를 기다리느라 환경 배치를 막지는 않습니다.

### 01. 변경 가능한 구조 마련

- [ ] 단일 `prologue.gd`에서 필요한 연결부만 분리합니다: 환경 장면 배치, 프롤로그 진행 상태, 전투 제어, 대화/안내. 대규모 전면 재작성은 피합니다.
- [ ] 환경 장면의 `grid_obstacles`를 기존 경로·충돌 배열에 등록하고 가려짐 대상도 연결합니다. StaticBody3D만 넣으면 현재 GridWalker가 피할 것이라 가정하지 않습니다.
- [ ] 탐험·대화·메뉴·전투 명령 정지·전투 실시간·암전 상태를 구분하고 입력 우선순위를 정의합니다. 대화의 Space가 전투 재개까지 전파되지 않게 합니다.
- [ ] 복수 boolean 대신 명확한 진행 단계와 이벤트 완료 기록을 마련합니다. 맵 이탈·재진입과 저장 복구 시 대화·적·약이 중복 생성되지 않게 합니다.
- [ ] 현재 저장 버전과 기존 기록을 보호합니다. 형식 변경 시 이관 또는 명확한 비호환 안내를 설계하며 무조건 삭제하지 않습니다.

완료 기준: 구조를 바꾼 뒤 기존 이동·대화·전달·저장 검사에 새 실패가 없습니다.

### 02. 서리골 한 맵을 미술·배치 기준으로 만들기

- [ ] 기존 집·여관·상점·민가·우물·문·울타리·가로등·나무를 개별 장면으로 교체합니다. 코드 생성물과 새 장면을 중복 배치하지 않습니다.
- [ ] 에일을 기준자로 놓고 문 폭, 창 높이, 우물·간판·나무의 화면 크기를 조정합니다. 기존 에셋은 출발점이며 최종 시각 품질이 승인된 것으로 간주하지 않습니다.
- [ ] 캐릭터 발 접지, 나무 알파 가장자리, 눈·돌길 반복, 건물 지붕과 모서리, 밝은 창의 대비를 실제 카메라에서 확인합니다.
- [ ] 상호작용 위치와 출구 접근성을 유지하고, 우물·장애물 주변의 한 칸 이동과 우클릭 우회를 검수합니다.
- [ ] 건물·나무 반투명과 카메라 경계를 확인합니다. 건물 일부만 남아 캐릭터를 가리는 경우도 점검합니다.
- [ ] 고정 구도로 에일·집·우물·길이 함께 보이는 화면과 짧은 걷기 영상을 제출합니다.

완료 기준: 이 서리골 화면을 다른 맵의 크기·색·밀도 기준으로 사용할 수 있습니다. 플레이 가능한 통로를 확보한 뒤 장식 밀도를 높입니다.

### 03. 집·산길·돌샘에 같은 기준 적용

- [ ] 집: 침대·탁자·약 선반·창·꾸러미를 연결하고 인물·가구·동선의 크기를 조절합니다. 아침 심부름 전후의 출발 조건을 적용할 공간을 준비합니다.
- [ ] 산길: 쉼터·흔적·레온 발견 위치·마물 접근로·전투 공간을 배치합니다. 발견 시 레온은 부상 상태이며, 길을 돌아 바로 돌샘으로 나가지 못하게 사건 진행과 연결합니다.
- [ ] 첫 전투 공간은 이동과 회피가 가능한 폭을 갖추되 뒤쪽 붕괴 지형과 적의 접근으로 즉시 도주가 어려운 이유가 보이게 만듭니다. 보이지 않는 벽만으로 설명하지 않습니다.
- [ ] 돌샘: 의무실 또는 연락소에서 약 인계와 레온 치료가 자연스럽게 연결되도록 수신자·위치를 고정합니다. 기존 대사에서 혼재된 배달 목적지를 정리합니다.
- [ ] 맵 전환의 스폰, 암전, 복귀 동선과 자동 저장을 검증합니다. 출입구 마커와 실제 위치를 맞춥니다.

완료 기준: 네 맵의 모든 필수 지점으로 갈 수 있고 사건용 공간·통로·충돌이 준비됩니다. 전투는 아직 임시 모형으로 연결할 수 있습니다.

### 04. 첫 전투의 최소 기능을 먼저 완성

- [ ] 에일·마물 1마리의 체력, 위치, 현재 행동, 공격 사거리와 행동 후 대기를 데이터로 관리합니다. 초기 숫자는 밸런스용 임시값입니다.
- [ ] 탐험하던 위치에서 전투를 시작하고 별도 맵 로딩 없이 명령 UI를 표시합니다.
- [ ] Space로 완전 정지·재개, 에일 선택, 이동 지점·공격 대상 지정과 취소를 구현합니다. 정지 상태에서 명령을 골라도 재개 전에는 시간이 흐르지 않습니다.
- [ ] 접근→사거리 확인→공격→행동 후 대기→반복을 구현합니다. 장애물 통과·벽 너머 타격·공격 후 대기 초기화 악용을 점검합니다.
- [ ] 적은 단순한 접근·공격을 하며, 레온은 공격 대상·명령 가능한 전투원에서 제외합니다.
- [ ] 일반 공격의 거리 이탈 또는 이동 명령으로 회피를 가르칠 수 있는지 검증합니다. 액션 회피 버튼이나 일반 공격 위험 바닥 표시를 무단 추가하지 않습니다.
- [ ] 승리·전투 불능·패배 전환과 임시 결과 화면을 연결합니다.

완료 기준: 임시 아트로도 한 전투를 시작→명령→공격→승리/패배까지 진행할 수 있습니다. 아직 도입하지 않는 마법·동료 4인 편성의 전체 구현을 선행 조건으로 삼지 않습니다.

### 05. 자원·아이템·재도전과 저장 경계

- [ ] 회복 아이템은 생존한 사용자·유효 대상·소지량·사용 가능 상태를 확인하고 효과/소비/행동 후 대기를 한 번만 반영합니다.
- [ ] ‘즉시 효과’와 ‘정지 중 소비를 즉시 확정할지’는 별개입니다. 후자의 미정 처리를 명시적으로 설계하여 정지 반복 입력으로 무한 사용하거나 취소 후 아이템이 복제되지 않게 합니다.
- [ ] 전투 시작 스냅샷과 소비 아이템 누적 기록을 분리합니다. 재도전은 체력·마나·위치·진행·보상을 돌리되 이전 시도에서 소비한 아이템까지 환급하지 않습니다. 두 번째 재도전도 첫 스냅샷의 수량으로 덮어쓰지 않습니다.
- [ ] 회복약을 전부 소모한 뒤에도 첫 전투를 이길 수 있는지 검증합니다. 자동 지급·환급으로 확정 규칙을 바꾸지 않습니다. 필요하면 무소비 승리가 가능하도록 적 수치·안내·안전한 재시작 위치를 조정합니다.
- [ ] 패배 시 긴 대화를 강제로 재생하지 않고 레온의 안내를 다시 볼지 선택하게 합니다.
- [ ] 전투 중 저장 허용 여부와 별개로, 전투 직전과 승리 후의 안전한 저장 지점을 정의합니다. 수동 불러오기와 전투 재도전의 차이는 명시하고 임의로 영구 소비 정책을 확대하지 않습니다.

완료 기준: 연속 패배·아이템 0개·재도전 반복·저장 복구에서도 진행 불가, 환급, 이중 차감, 보상 중복이 없습니다.

### 06. 레온 발견부터 첫 전투·동행까지 연결

1. 흔적 조사 → 부상당한 레온 발견과 상태 확인.
2. 깨진 공명석과 도움을 요청하지 못한 이유 제시 → 응급처치 시작.
3. 처치 완료 전에 마물 등장 → 에일의 위협·돌 던지기가 통하지 않음.
4. 레온이 일어서려다 상처 때문에 주저앉음 → 피하기 어려운 상황 확인.
5. 두려워하는 에일에게 레온이 검을 빌려주고 두 손으로 잡는 법을 알려줌.
6. 정지·명령·재개 → 이동 → 공격 → 행동 후 대기 → 적을 보고 위치 변경 → 자력 마무리 순의 안내.
7. 에일이 직접 승리 → 떨리는 손과 레온의 감사 → 붕대 처치 마무리.
8. 검은 돌샘까지 임시 대여 → 레온의 길 안내와 동행 → 돌샘 도착.

- [ ] 튜토리얼은 대사만 읽었는지가 아니라 해당 행동의 성공을 확인합니다. 수행한 설명은 반복 강제하지 않고 필요한 경우 다시 볼 수 있게 합니다.
- [ ] 에일의 공포와 레온의 판단력을 보여주되 레온이 대신 공격하거나 에일을 무책임하게 연습시키는 인상을 피합니다.
- [ ] 레온은 치료 직후 완치되지 않습니다. 동행 표현은 부상 포즈·느린 걸음과 안내로 일관되게 유지합니다.
- [ ] 전투 시작 트리거·적 생성·검 대여·승리·보상·자동 저장은 각 1회만 확정됩니다. ‘레온과 대화함’ 하나로 전투를 건너뛰던 기존 문턱을 교체합니다.

완료 기준: 발견부터 돌샘까지 정상 진행·패배 재시도·맵 재진입을 해도 사건 순서가 유지됩니다.

### 07. 나머지 프롤로그 서사와 탐험의 호흡 완성

- [ ] 방의 지도·배 그림, 마르타와 아침 대화, 우물·여관 심부름, 배달 요청, 준비와 배웅을 실제 진행으로 연결합니다.
- [ ] 필수 심부름은 수행 순서를 바꿔도 진행됩니다. 눈사람·주민 대화 등 선택 이벤트는 하지 않아도 본편이 막히지 않습니다.
- [ ] 마르타의 건강과 길 상황으로 에일이 대신 배달하는 이유를 보여줍니다. ‘약 챙기기’만 있는 현 빌드에 설정을 과도한 설명 대사로 덧붙이지 않습니다.
- [ ] 산길 자유 이동·쉼터·흔적 조사와 이벤트 전환을 조율합니다. 연출이 이어져 장시간 조작하지 못하는 구간은 줄입니다.
- [ ] 도구 사용 퍼즐·편지·요새 교차 연출은 대본 검토 결과에 따라 넣습니다. 불필요한 새 시스템이나 수집 의무를 만들지 않습니다.
- [ ] 목표 안내는 에일이 아는 내용으로 갱신합니다. 아직 알 수 없는 적의 정체나 세계의 비밀을 퀘스트 제목으로 스포일러하지 않습니다.

완료 기준: 초심자가 레온을 돕는 이유·배달 목적지·현재 목표·함께 이동하는 이유를 설명할 수 있습니다. 30~45분 목표는 플레이 측정 후 평가하며 길이나 대사로 억지로 늘리지 않습니다.

### 08. 동작·표정·UI·음향으로 플레이 감각 완성

- [ ] 에일의 검 대여 전후 모습을 구분하고 대기·걷기·공격·피격·전투 불능을 제작합니다. 레온의 부상·검 전달, 에일의 처치·첫 승리 후 동작을 준비합니다.
- [ ] 48×64 기본 캔버스·발 기준점·4방향과 실제 다리 프레임 원칙을 지킵니다. 반전 시 검을 든 손·가방의 비대칭을 확인합니다.
- [ ] 공격의 타격 시점, 피해 표시·피격·소리, 아이템 사용 효과, 행동 후 대기와 재개 상태가 읽히게 만듭니다. 마우스 대상/지점이 혼동되지 않도록 표시합니다.
- [ ] 주요 인물 표정별 초상화를 대사 감정에 맞춰 연결하고 과도한 전신 보드 크롭·늘어짐을 정리합니다.
- [ ] 제목·마을·산길·위기/전투·승리·동행에 필요한 BGM과 최소 효과음을 연결합니다. 발소리 반복·메뉴음·문·검·피격·아이템 소리를 점검합니다.
- [ ] 음원·폰트·외부 에셋의 출처와 사용 권한을 기록합니다. 음성은 제작하지 않습니다.
- [ ] 글자 확대·키 변경 후에도 UI·튜토리얼 안내와 실제 입력이 일치하는지 확인합니다.

완료 기준: 무음·글자 확대 등 환경에서도 조작 상태를 파악할 수 있고, 전투와 인물 감정에 필수 피드백이 누락되지 않습니다.

### 09. 회귀·완주·경계 상황 검수

- [ ] 기존 이동·환경 에셋 검사 유지. 이벤트 단계 전이, 튜토리얼 복구, 공격 반복·취소·아이템·승패·재도전에 동작 단위 검증을 추가합니다.
- [ ] 집 준비 전후, 배웅 직후, 레온 발견 전, 첫 전투 직전, 승리 후, 돌샘 전달 후의 저장/불러오기를 확인합니다.
- [ ] 맵 왕복, 필수 지점 접근, 이동 도중 대화·메뉴, 암전 중 연타, 대상 사망 직전 중복 명령, 공격 직후 정지를 검수합니다.
- [ ] 적 처치 보상·약 전달 보상·검 대여가 재진입·로드로 중복되는지 확인합니다. 보상 종류와 양은 미정이면 임시값으로 표시합니다.
- [ ] 개발 지식이 없는 플레이어가 안내 없이 처음부터 끝까지 플레이하게 하고 막힌 지점·읽지 못한 안내·실제 소요 시간을 기록합니다.
- [ ] 스토리/전술 모드 모두 진행 불가가 없는지 확인합니다. 난이도로 대사·관계 보상을 바꾸지 않습니다.
- [ ] 실제 화면과 영상으로 접지·가려짐·재질·타격·자막을 검토합니다. 자동 테스트 통과만으로 시각 완성을 선언하지 않습니다.

완료 기준: 진행 차단·저장 손상·아이템/보상 중복·필수 조작 미안내 문제 0건. 사소한 미술 수정은 알려진 문제 목록으로 분리할 수 있습니다.

### 10. Windows 전달 빌드와 최종 인계

- [ ] 현재 Godot 버전에 맞는 export templates로 Windows 실행 파일을 내보냅니다. 소스 저장소와 빌드 산출물은 분리합니다.
- [ ] 실제 Windows에서 새 게임→첫 전투→패배/재도전→돌샘 완료와 종료/재실행→불러오기를 확인합니다. Mac 또는 Linux 헤드리스 결과를 Windows 검증으로 대체하지 않습니다.
- [ ] 1280×720 및 확대 창의 UI, 입력·한글·세이브 경로·소리, 가장 무거운 맵에서의 프레임 시간을 기록합니다. 성능 목표는 측정 기기와 함께 정합니다.
- [ ] 실행 안내·키 목록·설정·세이브 위치·알려진 문제·검증 OS/기기·커밋·파일 체크섬을 빌드에 동봉합니다.
- [ ] Steam 업적·클라우드·배포 등록은 별도 범위입니다. 프롤로그 확인을 위해 불필요한 Steam 연동을 선행시키지 않습니다.

완료 기준: 다른 작업자가 지정 빌드를 받아 재현 가능한 방법으로 프롤로그를 완주하고 문제를 보고할 수 있습니다.

## PR와 진행 기록 운영

권장 PR 묶음은 위 단계의 완료 기준을 유지하면서 다음처럼 나눕니다. 아직 어떤 실행 PR도 이 계획 때문에 자동 생성하거나 착수하지 않습니다.

1. 00~01: 기준·진행 상태·에셋 연결부와 회귀 검사.
2. 02: 서리골 배치와 실제 화면/걷기 검토.
3. 03: 집·산길·돌샘 확대 및 동선 검사.
4. 04~05: 전투·자원·재도전. 구현량이 크면 두 PR로 분리.
5. 06: 레온 첫 전투 이벤트와 안내.
6. 07~08: 전체 서사·표정·음향·UI. 시나리오와 표현을 나눠도 됨.
7. 09~10: 완주·Windows 검증과 전달 자료.

각 PR에는 바뀐 플레이, 실제 검증, 미검증 환경, 적용 화면/영상, 남은 문제를 적습니다. main에 직접 푸시하지 않고 PR로 검토합니다. 서리골 검토 결과를 반영한 후 나머지 맵에 스타일을 확대합니다.

## 이번 계획에서 뒤로 미룰 것

본편 4인 파티 전체 AI, 마법 전체 목록, 전문화·장비 경제·연애 시스템, 전 대륙 맵, 1장 전체, Steam 서비스 기능은 첫 제작본의 필수 선행 조건이 아닙니다. 프롤로그가 사용하지 않는 기능을 먼저 구현하다가 이야기와 첫 전투가 미완성으로 남지 않게 합니다.
