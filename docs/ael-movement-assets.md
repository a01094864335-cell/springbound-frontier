# 에일 이동 동작 시제품

2026-10-30 · [조작·재생 뷰어](../assets/ael-movement/index.html) · [파일·프롬프트·검토 메모](../assets/ael-movement/manifest.json)

기존 에일 보드의 갈색 머리·초록 망토·크림 튜닉·약초 가방을 참고해 이동용 투명 PNG 8장을 제작했습니다. 맨손, 한손검, 창, 활, 단검, 지팡이, 한손검+방패, 단검+버클러를 각각 분리했습니다. 각 시트는 4행×8열, 총 32칸이며 전체 256칸입니다. 이는 고유 동작 256종이나 최종 애니메이션 256개의 의미가 아닙니다.

## 방향과 프레임

원본 PNG는 1536×1024 RGBA, 셀은 192×256입니다. 48×64는 몸체 픽셀 디자인의 기준이며 이번 파일을 그 규격의 최종 네이티브 도트로 간주하지 않습니다. 4배 크기 시안의 픽셀 밀도와 원점은 정리해야 합니다. 행은 아래·위·왼쪽·오른쪽, 열은 대기 1개 / 걷기 6개 / 정지 1개입니다. 클립의 인덱스는 manifest를 따릅니다.

- 대기: 1열의 정지 자세. 호흡 루프는 이번 범위에 없습니다.
- 출발: 현재 방향에서 걷기 첫 프레임으로 연결합니다. 별도 가속·출발 클립은 없습니다.
- 걷기: 2~7열의 발·다리·망토 변화. 전진과 역방향 이동은 해당 바라보는 방향의 걷기를 사용합니다.
- 방향 전환: 한 걸음을 마친 뒤 다음 입력 방향 행으로 전환합니다. 대각선·중간 회전 애니메이션·뒷걸음 전투 스텝은 추가하지 않습니다.
- 정지: 한 걸음 완료 후 8열을 잠시 표시하고 대기로 돌아갑니다. 정지·출발이 각각 독립 다중 프레임 클립으로 완성된 것은 아닙니다.
- 연속 이동: 누르고 있는 방향을 다음 걸음에 반영합니다. 동시에 여러 방향을 누르면 뷰어에서는 마지막 입력을 우선합니다. 이 우선순위와 속도는 검토용이며 게임 조작의 추가 확정사항은 아닙니다.

## 뷰어 사용

ZIP을 모두 압축 해제한 뒤 `assets/ael-movement/index.html`을 Chrome/Safari로 엽니다. 서버나 외부 라이브러리를 사용하지 않습니다. WASD·방향키로 한 칸씩 이동하며, 버튼으로도 한 걸음씩 확인할 수 있습니다. 속도 조절, 일시 정지, 장비 선택, 위치 초기화, 원본 시트를 제공합니다. 격자 배경은 검토용이며 기존 마을·NPC·적군·몬스터를 조합한 플레이 장면은 다음 작업입니다.

## 제작 검토와 가드레일

8장 모두 방향과 장비·프레임 구성을 시각 확인하고 PNG 크기·투명 채널을 검사했습니다. 배경에 투명 픽셀이 있지만 가장자리와 몸체에 반투명 픽셀이 있으므로 최종 알파 정리가 필요합니다. 장비별 신체 크기와 셀 안의 머리·발 위치에 미세한 편차가 있고 걷기 중 다리 자세가 유사한 프레임이 있어 자연스러운 6단계 보행으로 정합화해야 합니다. 뷰어는 원본을 균등 분할해 보여주므로 이 편차를 숨기지 않습니다.

가방 위치가 좌우 방향에서 반전돼 보이는 부분, 활의 손과 화살통 위치, 창·지팡이의 양손 그립, 오른쪽 옆모습에서 방패가 보이거나 가려지는 일관성을 최종 프레임 제작 때 수정해야 합니다. 단순 좌우 반전만으로 장비 손을 확정하지 않습니다. 몸·장비 레이어 분리, 프레임별 발 원점, 셀 크기 통일과 최종 클립 타이밍은 후속 단계입니다. 현재는 **재생 가능한 이동 시제품**이며 Godot 연결·출시용 애셋 승인 상태가 아닙니다.

확정 기획의 상하좌우 한 걸음 이동을 따릅니다. 달리기·대시·점프·구르기·등반·수영은 확정하지 않았으므로 이번 이동 세트에 새 기능으로 추가하지 않았습니다. 위험 범위 회피는 현재 이동으로 범위를 벗어나는 방식이며 전용 회피 기술을 승인한 것이 아닙니다. 장비 변경 UI는 시각 검토용이며 실제 장비 보유·직업 제한·교체 가능 시점을 구현하지 않습니다. 프롤로그는 기존대로 레온에게 검만 빌리므로 검 단독 이동을 사용하며 방패를 자동 지급하지 않습니다.

## 게임 연결 전 순서

1. 맨손·검 단독부터 발 원점·6단계 보행·가방 좌우 정합화.
2. 같은 몸체 기준으로 나머지 무기·방패 상태 정합화.
3. 실제 크기의 마을 배치에서 발 미끄러짐·벽 충돌·방향 전환·중단 후 재개 확인.
4. 장비 데이터와 이동 클립 연결, 저장/로드와 맵 전환 검증.
5. 기존 환경·NPC·몬스터를 배치한 플레이 화면 제작.
