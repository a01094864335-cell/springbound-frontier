# MQ11~15 외부 로컬 구현 인계

2026-11-06 · 제작 초안. 현재 환경에서는 문서만 작성하고 다른 로컬에서 게임 구현·실행·검수를 진행한다.

## 입력·출력·우선순위

입력은 MQ10 완료, 수송대 대기소 인계, 교량 제한·미통과 민간인 위치 확인, MQ11 시작 전 안전 지점이다. [귀환 편](../homecoming/README.md)에 이어진다. 출력은 MQ15 완료, 지원 요청과 조사 자료를 왕도 외곽 창구에 각각 접수하고 MQ16을 시작할 준비를 한 상태다. 실베르 면담과 공식 발표 확인은 이번 범위에서 재생하지 않는다.

[확정 기획](../../confirmed-design.md)과 [인물 설정](../../characters.md)을 우선하며 [이야기 규칙](../story-bible.md), [전투 명세](battle-spec.md), [전체 대본](full-script.md), [검수표](acceptance.md)를 함께 읽는다. 신규 수치·편성·적 종류·전투 기한 등 미확정 제안은 구현 전에 현행 규칙과 대조한다. 이 문서는 엔진 코드나 런타임 대화 파일이 아니다.

## 이번 상세화의 결정과 이전 제안 조정

- 레온은 **교량 편에서도 비전투**다. 귀환 편에서 싸울 수 없다고 한 뒤 갑자기 회복해 전투에 참여하지 않는다. A안에서 연락·명부·인수 통로를 맡는다. 기존 프롤로그 명세의 ‘교량 장 시작 전 회복 판정 뒤 전투 합류’ 제안보다 이 상세안의 **합류 유보**를 우선하는 작업안이다. 확정 기획의 최초 부상 규칙을 변경하지 않는다.
- 실제 전투 편성은 에일·리아 2인이다. 탐험 조작은 에일, 전투에서는 둘에게 각각 명령한다. 최대 4인은 상한이며 이 장에서 억지로 인원을 채우지 않는다.
- 레온이 ‘통로를 비운다’는 기존 발췌는 직접 검을 들고 막는 일이 아니라 A안의 인수·수비 담당자 배치를 확인한다는 뜻으로 상세화한다. 그의 국적은 확정하지 않는다.
- 구조 대상은 **B안에 남은 다른 민간 수레**다. 이미 대기소에 있는 서리골 환자 수레가 갑자기 강 건너로 옮겨진 것이 아니다.
- 제한 통행 허가는 수리·구조 인원과 귀환 수레에 대한 현장 예외다. 교량 전체가 평상시처럼 재개통되었다는 뜻이 아니다.
- 리아는 MQ14에서 동행 의사를 밝히고 MQ15에서 현장 근무를 인계한다. 선택 개인 이벤트를 하지 않아도 본편 역할과 동행은 성립한다.

## 위치 표기

| 구역 | 위치·사람 | 이 장에서 하는 일 |
|---|---|---|
| 후방 대기소 | 서리골 첫 수송대, 기존 구호 담당자 | 안전 대기 유지. 교량 구조 대상과 별도 명부 |
| A안 | 에일이 접근한 쪽의 교량 안쪽, 수비 책임자·레온·인수 담당자 | 제한 통행, 받는 곳, 철수 구역과 후속 야영지 |
| 교량 | B→A 수송로, 별도의 퇴로 표식 | 수레와 구조대가 돌아오는 통로. 지형 장애물 검토 |
| B안 | 아직 수비대가 접근 가능한 바깥쪽 진입로, 고장 난 수레·리아·수리병 | 수리·탑승·저지 후 A안으로 철수 |
| 적 접근로 | B안 외곽, 정찰로 확인한 구간 | 추격 병력 진입. 적 본거지로 확장하지 않음 |
| 왕도 외곽 | MQ15 마지막 이동 뒤 | 자료 수령 기록, 다음 담당 부서 안내 |

준비 단계에서 A→B 제한 접근, 전투 단계에서 B→A 철수다. 정확한 동서남북·강 이름·맵 치수는 월드맵 검토 뒤 정한다. 화면 위쪽이 항상 적국이라는 임의 설정을 넣지 않는다. 교량 붕괴·폭파는 이번 결말에 추가하지 않는다. 폐쇄와 방어 인계를 파괴 연출로 대체하면 후속 이동 설정이 바뀐다.

## 장면·조작·완료 연결

| MQ | 장면 | 조작 | 필수 완료 | 다음 흐름 |
|---|---|---|---|---|
| MQ11 | B01~B04 | 대기소 출발→수비 정보→리아 소개→조건 합의 | 접근 보고·미통과 민간인·수비/퇴로 기준 확인 | 제한 통행으로 B안 접근 |
| MQ12 | B05~B08, B07A/B 한쪽 | 수레 확인→퇴로와 수송 인수 확인(순서 자유)→수리/탑승 | 실제 수리·탑승·퇴로 확인 | 전투 준비 |
| MQ13 | B09~B10, E01~03, B11 | 2인 명령→호위/저지→두 사람 철수 | 필수 수송 인수+출전 2인 철수 | 야영지 명부 대조 |
| MQ14 | B12~B14 | 도착·치료·미확인 구분→출처·동의 범위 기록 | 분류·증언·허가 확인 | 리아 동행 의사·SE04 해금 |

### 조건과 순서

B02와 B03의 현황을 확인한 뒤 B04를 재생한다. 인물 소개를 건너뛴 채 리아를 편성하지 않는다. B05 뒤 퇴로(B06)와 수송 인수(B07→A/B)는 순서 자유다. 두 조건을 갖추면 B08에서 수리병의 실제 작업 완료와 시험 이동·탑승을 보여준다. 대사창을 닫았다고 수레가 수리된 것으로 처리하지 않는다.

B09~10의 준비·설명 단계에는 전투 제한 시간이 흐르지 않는다. 설정·장비 확인 뒤 시작을 명시적으로 확정한다. B11은 단순 수레 도착이나 적 전멸만으로 재생하지 않는다. 자세한 판정은 전투 명세를 따른다.

B12~13은 최초 신규 경로에서 필수다. SE04 같은 선택 장면에 핵심 진실을 숨기지 않는다. B14 마지막에 MQ14 완료와 SE04 해금을 처리한다. B15~17의 현장 인계를 마친 뒤 B18 출발/머물기를 선택한다. 머무르면 MQ15 미완료의 준비 상태로 야영지에 남고 SE04를 할 수 있다.

B18의 이동은 시간 경과와 도로 이동 장면으로 연결한다. 다음 장의 지원 창구를 만난 것과 실제 지원 물자가 출발한 것은 다르다. B19는 수령 번호와 수신 부서를 확인하고 MQ15를 끝낸다. MQ16 미구현 시 왕도 외곽 안전 지점에서 멈춘다.

## 정보와 인물의 경계

이번 장의 적은 접근 보고와 실제 교전으로 확인한다. 적 국가 지휘관의 전체 목적·시설 운용 책임·최종 배후를 병사의 대사로 확정하지 않는다. 병력의 구체 소속·보드 배정은 기존 적군 목록과 지도 검토 뒤 정한다. 명분을 설명한다는 이유로 민간 피해 책임을 지우지 않는다.

리아는 현실적인 구조 담당자이며 위험을 전혀 모르는 무모한 사람으로 만들지 않는다. 처음에는 남은 사람을 우선 묻지만 시간·통로·인수자까지 합의하고, 직접 정한 철수 기준을 따른다. 에일이 혼자 리아를 설득해 성장시킨다는 구도로 축소하지 않는다.

레온이 비전투라는 이유로 모든 결정을 대신 내리는 전지적 지휘관도 아니다. 정찰 미확인 구간과 자신의 부상 한계를 밝히고 각 담당자의 확인을 받는다. 에일은 처음 전투 경험을 늘려가는 단계다. 창을 쓰는 리아의 행동을 보며 역할 분담을 익히되 직업 선택을 확정하지 않는다.

## 통신과 예비대

교량 양안의 짧은 신호, 신호병의 복창, 표식, 전령을 사용한다. `레온의 전달`은 B안 신호 담당자가 받은 내용을 전하는 대사다. 긴 문장을 실시간으로 마법 전송하지 않는다. 자세한 계획은 건너가기 전에 합의한다.

신호가 없으면 준비 완료라고 추정하지 않는다. 정해둔 표식·예비 신호·철수 기준으로 돌아온다. 예비대는 구조대가 돌아올 때 방어를 넘겨받는 인력이며 **필수 수레를 못 구해도 자동 성공시키는 장치가 아니다.** 수레 미인수·출전 인원 미철수는 해당 조건에 따라 실패와 재도전으로 처리한다.

## 명부·증언·자료 인계

도착 확인, 치료 인계, 확인 대기, 다른 경로 이동 보고를 구분한다. 확인 대기를 곧 사망으로 쓰지 않는다. 교량에서 실제 인수한 필수 수송 인원을 감정 연출을 위해 다시 실종 처리하지 않는다. 마르타 일행은 확인된 최신 위치만 유지한다. 이 범위에서 귀환·도착 확인을 새로 쓰지 않았으면 자동으로 모두 도착시킬 수 없다.

증언자의 선택은 공개/익명/제한 보관 범위다. 동의를 받지 못한 개인 정보는 보호하고, 통행 명령·구호 인수·현장 담당자 진술 같은 필수 근거를 별도로 확보한다. 자료 자체를 버리거나 원본을 훔치는 선택은 없다. 현장 원본 보관과 허가 사본, 보관처·인계자·왕도 수령 번호를 연결한다.

지원 요청은 당장 필요한 인원·물자·현장 수용 여력, 조사 자료는 기록의 출처·시기·불확실성이다. 조사 결론이 나기 전 지원을 요청할 수 있어야 한다. B19의 접수는 실제 배정·출발 확인이 아니며 그 차이는 MQ16 이후 본편에서 다룬다.

## SE04 ‘잘린 밧줄’

기존 [서브 원본](../side-events.json)의 ID·해금·기한을 유지한다. MQ14 완료 후 야영지에서 시작하고 후반 구호 거점에서도 재개한다. 기간 한정 경고나 출발 전 자동 실패를 추가하지 않는다.

S04_1의 감정 대화→S04_2 한 가지 선택→S04_3 마무리다. 명부부터 보는 선택과 수선하며 듣는 선택은 반응 순서만 다르다. 구조 인원·실종자·관계 보상의 정답 선택으로 쓰지 않는다. 연애는 시작되지 않는다.

거점을 옮겼어도 같은 ID의 단계·선택·완료를 유지한다. 후반에는 지난 기록 사본과 보관한 밧줄을 보고 대화하며 원래 교량 야영지로 강제 이동시키지 않는다. 한 번 완료하면 짧은 재대화로 바꾼다. 손상 밧줄은 연습용 소품이며 검증 없이 인명 구조 장비로 지급하지 않는다.

## 상태·저장·옛 자료 접점

| 의미 상태 | 반영 시점 | 불변 조건 |
|---|---|---|
| MQ11 현황/리아 소개/제한 통행 | 각 대화 종료·B04 합의 | 소개 전 편성 불가, 군 수송 제한 해제와 혼동 금지 |
| MQ12 수송/퇴로/수리/탑승 | 확인·실제 작업 완료 | 선택 A/B 중복 실행 금지 |
| MQ13 전투 전 보관/소비 이력 | 전투 시작/아이템 실제 사용 | 실패 시 소비품 미복구 |
| MQ13 수송 인수/2인 철수/승리 | 실제 판정 | 전멸만으로 승리 금지, 보상 1회 |
| MQ14 분류/출처/공개 범위 | 각 마지막 페이지 | 재대화가 생사·동의 변경하지 않음 |
| MQ14 완료/SE04 해금 | B14 종료 | 개인 이벤트와 본편 동행 독립 |
| MQ15 현장 인계/서류/편지 태도/출발 | 각 완료·출발 확인 | 미선택 편지 분기 실행 금지 |
| MQ15 왕도 수령/MQ16 준비 | B19 종료 | 접수≠지원 완료 |

상태 이름은 제안이다. 기존 스키마와 매핑하고 세이브 버전·슬롯 정책을 임의로 확정하지 않는다. 대화 종료의 완료 반영과 저장은 일관되게 처리하고, 기록창 재열람·메뉴·선택 취소로 보상·소비·편성이 반복되지 않게 한다. 전투 밖 자유 저장과 전투 전 보관을 지킨다.

구버전에 리아·전투·명부 플래그가 없는 경우 진행 위치만 보고 ‘전투 승리’로 소급하지 않는다. 이미 후속 장을 구현한 다른 로컬은 현행 진행 우선순위를 조사해 별도 이관안을 제시한다. MQ10 완료 기록은 정상 입력 접점이다. 이전 제안대로 레온이 이미 편성된 개발 저장은 부상 상태와 계획을 확인해 이행하며 장비·캐릭터를 조용히 삭제하지 않는다. 문서 추가가 저장 이관 구현을 완료한 것은 아니다.

## 자산·연출·작업 순서

[인물/NPC 목록](../../npc-registry.md), [리아·레온 설정](../../characters.md), [적군 보드](../../enemy-character-boards.md), [장비·모션](../../combat-equipment-and-motion-spec.md), [환경](../../environment-assets.md)을 참조한다. 이미지 보드를 실제 걷기·공격·부상·수레 이동·명령 UI의 완료로 보지 않는다. 적은 병사·기사 계열 후보에서 역할과 가독성에 맞춰 고르며 신규 고유 보스를 필수로 추가하지 않는다.

필수 표현은 창을 든 리아, 임시 검 에일, 부상 레온, 수리/구조 NPC, 수레·들것·표식·바리케이드·교량·양안이다. 리아의 무기는 직업 범위에 맞추고 에일의 전 무기 선택 가능성을 삭제하지 않는다. 이번 전투에서 방패/새 무기 교습·마법을 강제하지 않는다.

카메라는 기존 고정 방향을 유지한다. 위험과 철수는 색만이 아니라 아이콘·텍스트·경로로도 표시한다. 고정 방향상 양안이 혼동되면 지형과 인수 표식으로 구분한다. 성공 연출은 모두 돌아왔음을 확인하는 짧은 안도이며 아직 미확인인 모든 사람의 구원을 선언하지 않는다. 음원·효과음은 사용 권한과 실제 파일을 선정 후 등록한다.

외부 로컬에서는 (1) 위치·스키마 대조 (2) MQ11~12 진행 (3) 2인 명령과 호위/철수 판정 (4) 실패·재도전·소비 규칙 (5) MQ14~15 및 SE04 (6) [검수표](acceptance.md) 순서로 작업한다. 현재 환경은 결과 링크와 기획 충돌을 받아 문서를 보완하는 역할을 유지한다.
