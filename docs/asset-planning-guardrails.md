## 1. 문서의 역할과 우선순위

이 문서는 지금까지 생성한 배경·인물·아이템·모션 시안의 상태와 구현 범위를 분명히 합니다. 제작 요청은 그림 생성의 허용이며, 그림 속 모든 세부가 게임 규칙이나 최종 설정으로 승인된다는 뜻은 아닙니다.

우선순위는 **최신 사용자 명시 지시 → 확정 기획의 최신 항목 → 채택된 상세 명세 → 시안·추천·미정**입니다. 기존 문서가 충돌하면 새 지시와 차이를 기록하고 오래된 문구를 근거로 되돌리지 않습니다.

## 2. 에셋 상태를 나누는 기준

| 상태 | 의미 | 아직 보장하지 않는 것 |
|---|---|---|
| 외형/키포즈 시안 | 디자인과 동작 방향을 비교하는 이미지 | 투명 배경·셀 규격·모든 프레임·최종 승인 |
| 제작용 정리 | 개별 파일·크기·원점·방향·메타데이터 검증 | 게임과 연결·플레이 검증 |
| 런타임 연결 | 엔진에서 참조하고 사건·애니메이션에 연결 | 화면·동선·밸런스가 적절하다는 검수 |
| 플레이 검증 | 실제 화면과 입력·이벤트 검수 | 모든 OS·기기 호환성 |
| 플랫폼 검증 | 목표 OS와 지정 빌드에서 검증 | 다른 환경까지 자동 보장 |

파일 수, 보드 안의 도안 수, NPC 타입 수, 실제 배치 개체 수를 구분합니다. 보드 안의 작은 도트는 그 자체로 정확한 48×64/32×32 투명 게임 에셋이 아닙니다.

## 4. 미술·표현 가드레일

- 캐릭터 일러스트는 고전 판타지 RPG의 또렷한 선·셀 채색, 인게임은 도트 표현. 원작의 실제 이미지·캐릭터·로고·음원을 복제하지 않습니다.
- 초록 망토·소박한 복장의 에일 정체성을 유지하고 금장·버클·보석을 무조건 늘리지 않습니다. 시안 안의 장식도 실제 작은 도트에서 단순화할 수 있습니다.
- 고정 사선 카메라와 화면 축 상하좌우 이동을 기준으로 합니다. 대각선 이동이나 카메라 회전을 시각 시안만 보고 추가하지 않습니다.
- 인물의 나이·체형·상태가 구분돼야 합니다. 같은 캔버스가 같은 신장과 체형을 뜻하지 않습니다. 어린이·노인의 보폭과 포즈는 별도 검수합니다.
- 긴 무기의 여백·발 원점·겹침을 설계합니다. 큰 무기를 넣으려고 몸체를 작게 하거나 발 위치를 프레임마다 흔들지 않습니다.
- 도트 확대는 선명한 픽셀을 유지합니다. 레이아웃 보드의 글자·여백·그림자를 캐릭터 런타임 프레임으로 가져오지 않습니다.
- 필드 소품·장착 외형·인벤토리 아이콘은 용도가 다릅니다. 필요한 것을 별도 제작하고 파일명과 데이터로 연결합니다.

## 5. 인물·장비·모션 가드레일

- 에일은 모든 무기 사용 가능. 다른 전투 인물은 직업별 무기 허용 목록. 방어구·장신구는 공용입니다.
- 장착 제한은 데이터 검증으로 확인합니다. 아이콘 색이나 버튼 표시만 막고 저장/로드·다른 경로로 우회 장착되게 두지 않습니다.
- 소지 가능과 장착 가능은 별개입니다. 제한 무기를 인벤토리에서 지우거나 보상으로 못 받게 하는 규칙을 자동 추가하지 않습니다.
- 주인공의 자유 장착을 무기 무료 지급·모든 기술 해금·전투 중 자유 변경으로 확대하지 않습니다. 동료의 개별 허용 무기, 장비 슬롯과 비용은 별도 결정입니다.
- 마르타·상인·주민에게 외형 보드가 있다고 전투 역할을 부여하지 않습니다. 병사도 진영만으로 적대 여부를 정하지 않습니다.
- 일반 승리 모션은 캐릭터성에 맞춰 설계합니다. 첫 전투의 떨림·레온 확인과 구분하고, 전투 불능자에게 서 있는 승리 모션을 실행하지 않습니다.
- 공격 판정·발사·아이템 소비·보상은 연출과 별도 상태로 관리합니다. 반복·중단·스킵·재도전에서 중복되지 않아야 합니다.

## 6. 프롤로그와 시스템 범위 가드레일

- 첫 제작본은 서리골 생활→약 배달→레온 발견→검 대여·첫 전투→처치·동행→돌샘입니다. 에셋 종류가 늘어도 본편·새 시스템을 전부 선행 구현하지 않습니다.
- 레온은 첫 전투에서 부상으로 싸우지 않으며 검을 빌려주고 안내합니다. 에일은 빌린 검·회복 아이템을 사용하고 마법은 이후 도입합니다.
- 아이템 즉시 효과와 사용자 행동 후 대기를 함께 유지합니다. 시전 중 사용·정지 중 처리 등 미정 사항은 임의 확정하지 않습니다.
- 패배 후 재도전의 소비 아이템 미환급 규칙을 지킵니다. 고갈 상황의 진행 가능성을 검증하되 몰래 무료 환급하지 않습니다.
- 체력·마나 유지, 정지 명령·별도 재개, 전투 불능·전원 패배, 공용 장비 등의 최신 결정을 표면 효과 때문에 바꾸지 않습니다.
- 상태 해제약·약초·야영 도구·장신구 외형이 존재해도 해당 상태이상·조합·허기·내구도·장비 슬롯 시스템 도입은 별도 범위입니다.
- 공명석·기념품·지도 외형이 확정 서사나 통신의 무제한 성능을 뜻하지 않습니다. 새 장비의 ‘고대’라는 이름만으로 최상급 수치·마법을 부여하지 않습니다.

## 7. 엔진·맵 연결 가드레일

- 3D 환경 장면의 StaticBody3D만으로 기존 GridWalker의 장애물 처리가 완료되지 않습니다. `grid_obstacles`와 가려짐 등록, 좌표 변환을 확인합니다.
- 새 건물 장면과 기존 생성 건물·소품을 중복 배치하지 않습니다. 출구·NPC·퀘스트 상호작용은 에셋과 별도 연결합니다.
- 저장 형식 변경은 버전·이관·비호환 안내를 명시합니다. 기록이 있다는 이유만으로 새 이벤트를 이미 완료 처리하거나 지급을 반복하지 않습니다.
- 현재 개발 테스트와 출시 환경을 구분합니다. Windows 출시 목표, Mac 개발 테스트이며 웹 우선 계획은 이전 결정입니다. HTML 도감은 게임 웹 배포가 아닙니다.
- 엔진 버전·렌더러 변경, 셰이더·그림자·한글 글꼴과 투명 재질은 실제 목표 환경에서 검증합니다. 헤드리스 테스트는 시각 검수를 대체하지 않습니다.

## 8. 납품·출처·리뷰 가드레일

- 생성 원본을 보존하고 `v1` 등 버전 파일과 manifest에 생성 도구·프롬프트·참고 자료·ID·해시·상태를 기록합니다. 수정하면서 기존 최종본을 조용히 덮어쓰지 않습니다.
- 외부 폰트·음원·도구를 쓸 때는 사용 권한과 출처를 기록합니다. 원작 전투 세부는 판본과 증거 수준을 함께 씁니다.
- 신규 변경은 브랜치와 PR로 올립니다. 계획·시안 PR과 런타임 구현 PR을 구분하며 main 직접 반영을 기본으로 하지 않습니다.
- 공개 저장소에는 작업용 요약과 요청한 에셋만 올립니다. 개인 대화 원문·환경 정보·인증 정보는 섞지 않습니다.
- HTML은 앱/GitHub에서 소스로 보일 수 있습니다. 다운로드 ZIP과 브라우저에서 여는 안내를 제공합니다. 상대 이미지가 필요한 갤러리는 HTML만 단독 배포하지 않습니다.
- 이미지·데이터 경로/개수/ID/해시는 기계 검증, 포즈·비율·실루엣은 시각 검토, 상태 전이·저장은 실행 검증으로 나누어 증거를 남깁니다.

## 9. 완료 보고에 반드시 적을 것

1. 무엇을 몇 **파일/보드/도안/타입** 만들었는지.
2. 외형 시안인지, 개별 게임 파일인지, 런타임에 연결했는지.
3. 실제로 수행한 시각·자동·플랫폼 검증과 미검증 범위.
4. 다음 제작 단계와 미정 규칙. 사용자 승인 없이 확정으로 바꾸지 않기.
5. PR·문서·다운로드 위치와 병합 여부.

## 방패 조합 가드레일

[방패 추가 기획](shield-loadouts.md)을 따릅니다. 무기 종류만으로 방패를 생성하지 않고 실제 보유·장착 상태를 확인합니다. 방어 키포즈가 있다는 이유로 패링·스태미나·무적 판정을 확정하지 않습니다. 방패 5종은 외형 대안이며 성능 등급이 아닙니다. 현재 결과물은 참고 보드이며 게임 코드 연결은 없습니다.

## 2026-10-30 첫 전투 구현 업데이트

[첫 전투](first-battle.md)에 현재 구현·프로토타입 수치·저장 v3·검증 범위를 기록했습니다. 이전 표의 초기 이동 빌드 설명과 구분합니다. 검 대여→같은 맵 전투→비환급 재도전→승리 후 처치→약 전달을 연결했으며, 캐릭터 보드·키포즈 전체가 최종 애니메이션으로 전환된 것은 아닙니다.
